# Lovers Compatibility

Развлекательный тест для пары на одном телефоне. Два человека отвечают по очереди, не видя ответы друг друга. В конце приложение показывает, где вы совпали, где разошлись и насколько точно каждый угадывал партнёра.

Это не психологическая диагностика и не научный тест.

Живая версия: https://lovers-compatibility.vercel.app/

## Запуск

Нужен Node.js 20+.

```bash
npm install
npm run dev
```

Сборка и локальный просмотр продакшена:

```bash
npm run build
npm run preview
```

Проверки:

```bash
npm test
npm run lint
npm run format:check
npm run lint:fsd
```

Перед коммитом husky запускает `lint-staged`: ESLint с автоисправлением и Prettier на изменённых файлах. Хук ставится командой `npm install` через скрипт `prepare`.

## Подключение AI

Модель в коде не выбрана. Живой разбор включается только через `.env` в корне проекта. Скопируйте пример и заполните все три строки:

```bash
cp .env.example .env
```

```env
VITE_AI_API_URL=
VITE_AI_API_KEY=
VITE_AI_MODEL=
```

- `VITE_AI_API_URL` — адрес OpenAI-совместимого API без завершающего слэша, например `https://api.openai.com/v1`. Клиент сам вызывает `/chat/completions`.
- `VITE_AI_API_KEY` — ключ этого API.
- `VITE_AI_MODEL` — имя модели у выбранного провайдера. Значения по умолчанию нет.

Если хотя бы одной переменной нет, сервис недоступен, ответ пришёл не тем JSON или запрос длится дольше 30 секунд, тест не пропадает: показывается локальный разбор и кнопка «Попробовать AI-анализ ещё раз».

Числовой процент считается на телефоне и не приходит от модели. Одинаковые ответы всегда дают одинаковый процент.

**Ключ во frontend не является секретом.** Vite вшивает `VITE_*` в сборку, и его может прочитать любой, кто откроет приложение. Для публичного продакшена так делать нельзя. Для свадьбы, демо и приватного деплоя это допустимо. Отдельный backend в этом проекте намеренно не добавляется.

## Офлайн

Приложение ставится как PWA. Опубликованная версия: https://lovers-compatibility.vercel.app/. Оболочка, вопросы и подсчёт работают без сети. AI-разбор требует интернет: без сети сразу используется локальный разбор.

Сессия хранится в `localStorage` этого устройства неделю. «Начать новую пару» стирает её.

## Как устроен проект

Слои Feature-Sliced Design, импорт только сверху вниз: `app` → `pages` → `widgets` → `features` → `entities` → `shared`.

- Вопросы, сессия, подсчёт и запасной разбор живут в `entities`.
- Запрос к модели — в `shared/api/ai` и подменяется другой реализацией того же интерфейса.
- Экраны только собирают интерфейс и не считают процент сами.
